## 1. Why Migrate Now & Core Philosophy

### Compile-Time Validation vs Runtime Crashes
In JavaScript, types only exist conceptually. If you pass an invalid status or access a property on an undefined object, your server crashes in production during a live request.

TypeScript catches these errors **at design-time** right inside your editor:
- **Enum Safety:** Guarantees that `"Pending" | "In Progress" | "Completed"` are spelled identically across controllers, queries, and database models.
- **Request Safety:** Express's default `req` object does not know about `req.user`. TypeScript forces you to define authenticated requests, preventing `TypeError: Cannot read properties of undefined (reading '_id')`.
- **IntelliSense & Autocomplete:** Eliminates the need to switch tabs to check schema field names.

## Step 1: Install TypeScript Dependencies

Navigate to the `server` directory and install the TypeScript compiler, type definition packages, and `tsx` (the modern, ultra-fast TypeScript execution tool for development):

```bash
cd server
npm install -D typescript @types/node @types/express tsx
```

### Why these packages?
* `typescript`: Provides the `tsc` compiler which validates types and transpiles TS to JS.
* `@types/node`: Provides type definitions for Node.js runtime globals (`process.env`, `Buffer`, `EventEmitter`, etc.).
* `@types/express`: Provides type definitions for Express (`Request`, `Response`, `NextFunction`, `Router`, `ErrorRequestHandler`).
* `tsx`: Executes TypeScript files directly without a manual compile step, featuring instant file watching and reloading (`tsx watch src/index.ts`). Replaces `nodemon`.

## Step 2: Configure `tsconfig.json`

Create `server/tsconfig.json` with the following configuration:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": "./src",
    "outDir": "./dist",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "noImplicitAny": true,
    "sourceMap": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```

### Key Option Breakdown:
- `"target": "ES2022"`: Compiles to modern JavaScript features natively supported by Node 18+.
- `"module": "NodeNext"` & `"moduleResolution": "NodeNext"`: Uses standard Node.js ECMAScript Modules (ESM).
- `"rootDir": "./src"`: Tells the compiler where the source code lives.
- `"outDir": "./dist"`: Directs the compiled production `.js` and `.map` files into `dist/`.
- `"strict": true`: Enables all strict type-checking options, preventing subtle bugs.
- `"esModuleInterop": true`: Allows default imports from CommonJS modules seamlessly.

## Step 4: Create Custom Global Types (`src/types/`)

### 1. `src/types/express.d.ts`
Extends Express’s `Request` interface so `req.user` is recognized globally without compilation errors.

```typescript
import { Document, Types } from "mongoose";

declare global {
  namespace Express {
    interface Request {
      user?: {
        _id: Types.ObjectId | string;
        email?: string;
        username?: string;
      };
    }
  }
}

export {};
```

## Step 5: Migrate Mongoose Models

### 1. `src/models/user.ts`
```typescript
import mongoose, { Document, Schema } from "mongoose";

export type TargetTier = "Service" | "Product" | "Big-Tech";

export interface IUser extends Document {
  username: string;
  email: string;
  password: string;
  targetLpa: number;
  targetTier: TargetTier;
  currentLpa: number;
  handles: {
    leetcode: string;
    codeforces: string;
  };
  createdAt: Date;
  updatedAt: Date;
}

const userSchema = new Schema<IUser>(
  {
    username: { type: String, required: true, trim: true },
    email: { type: String, required: true, unique: true },
    password: { type: String, required: true },
    targetLpa: { type: Number, required: true },
    targetTier: {
      type: String,
      enum: ["Service", "Product", "Big-Tech"],
      required: true,
    },
    currentLpa: { type: Number, default: 0 },
    handles: {
      leetcode: { type: String, default: "" },
      codeforces: { type: String, default: "" },
    },
  },
  { timestamps: true }
);

export const User = mongoose.model<IUser>("User", userSchema);
```

### 2. `src/models/task.ts`

import mongoose, { Document, Schema, Types } from "mongoose";

export type TaskCategory = "DSA" | "Development" | "Contest";

      type: String,

## Step 6: Migrate Config, Middlewares & Services

### 1. `src/config/db.ts`
```typescript
import mongoose from "mongoose";

const connectDb = async (): Promise<void> => {
  try {
    const mongoUri = process.env.MONGO_URI;
    if (!mongoUri) {
      throw new Error("MONGO_URI environment variable is not defined");
    }
    await mongoose.connect(mongoUri);
    console.log("MongoDB connected successfully");
  } catch (error) {
    console.error("MongoDB connection error:", error);
    process.exit(1);
  }
};

export default connectDb;
```

### 2. `src/middlewares/errorHandler.ts`
```typescript
import { Request, Response, NextFunction, ErrorRequestHandler } from "express";

const errorHandler: ErrorRequestHandler = (
  err: Error,
  _req: Request,
  res: Response,
  _next: NextFunction
): void => {
  const statusCode = res.statusCode === 200 ? 500 : res.statusCode;

  res.status(statusCode).json({
    success: false,
    message: err.message,
    stack: process.env.NODE_ENV === "production" ? null : err.stack,
  });
};

export default errorHandler;
```

### 3. `src/services/llmService.ts`
Fixes the `"prompt"` string literal bug and specifies expected return types:

```typescript
import OpenAI from "openai";

const openai = new OpenAI({
  apiKey: process.env.OPENAI_API_KEY,
});

export interface GeneratedTask {
  title: string;
  category: "DSA" | "Development" | "Contest";
  resourceLink: string;
  lpaWeight: number;
}

export interface GeneratedWeek {
  weekNumber: number;
  focusArea: string;
  tasks: GeneratedTask[];
}

export interface RoadmapJSONResponse {
  weeks: GeneratedWeek[];
}

export const generateRoadmapJSON = async (
  targetTier: string,
  targetLpa: number
): Promise<RoadmapJSONResponse> => {
  const prompt = `
    You are an expert Senior Software Engineer. Create a strict 4-week study roadmap for a developer aiming for a ${targetLpa} LPA job at a ${targetTier} tier company.
    
    RULES:
    1. Select resources ONLY from these verified sources: Striver A2Z (DSA), Neetcode 150 (DSA), FreeCodeCamp (Dev), LeetCode Contests.
    2. Adjust the DSA vs Development ratio based on the Tier (Big Tech needs heavy DSA, Service needs more Dev).
    3. Output EXACTLY in this JSON format, nothing else:
    {
      "weeks": [
        {
          "weekNumber": 1,
          "focusArea": "String",
          "tasks": [
            { "title": "String", "category": "DSA", "resourceLink": "URL", "lpaWeight": 0.5 }
          ]
        }
      ]
    }
  `;

  const response = await openai.chat.completions.create({
    model: "gpt-4o-mini",
    messages: [{ role: "system", content: prompt }], // Fixed variable reference!
    response_format: { type: "json_object" },
  });

  const content = response.choices[0]?.message?.content;
  if (!content) {
    throw new Error("Failed to receive response from OpenAI");
  }

  return JSON.parse(content) as RoadmapJSONResponse;
};
```

## Step 7: Migrate Controllers & Routes

### 1. `src/controllers/roadmapController.ts`
```typescript
import { Request, Response, NextFunction } from "express";
import { Roadmap } from "../models/roadmap.js";

export const getMyRoadmap = async (
  req: Request,
  res: Response,
  next: NextFunction
): Promise<void> => {
  try {
    if (!req.user?._id) {
      res.status(401);
      throw new Error("Not authorized, user missing");
    }

    const roadmap = await Roadmap.findOne({
      userId: req.user._id,
      isActive: true,
    }).populate({ path: "weeks.tasks", model: "Task" });

    if (!roadmap) {
      res.status(404);
      throw new Error("No Active roadmap found. Please generate one first.");
    }

    res.status(200).json({ success: true, data: roadmap });
  } catch (error) {
    next(error);
  }
};
```

### 2. `src/controllers/taskController.ts`
```typescript
import { Request, Response, NextFunction } from "express";
import { Task, TaskStatus } from "../models/task.js";

export const updateTaskStatus = async (
  req: Request<{ id: string }, {}, { status: TaskStatus }>,
  res: Response,
  next: NextFunction
): Promise<void> => {
  try {
    const { status } = req.body;
    const allowedStatuses: TaskStatus[] = ["Pending", "In Progress", "Completed"];

    if (!allowedStatuses.includes(status)) {
      res.status(400);
      throw new Error("Invalid status update");
    }

    const task = await Task.findById(req.params.id);

    if (!task) {
      res.status(404);
      throw new Error("Task not found");
    }

    task.status = status;
    await task.save();

    res.status(200).json({ success: true, data: task });
  } catch (error) {
    next(error);
  }
};
```

## Step 8: Migrate Entry Point (`src/index.ts`)

```typescript
import express, { Application } from "express";
import dotenv from "dotenv";
import connectDb from "./config/db.js";
import errorHandler from "./middlewares/errorHandler.js";
import roadmapRouter from "./routes/roadmapRoutes.js";
import taskRouter from "./routes/taskRoutes.js";

dotenv.config({ path: ".env" });

const app: Application = express();

// Body Parser Middleware
app.use(express.json());

// API Routes
app.use("/api/v1/roadmap", roadmapRouter);
app.use("/api/v1/task", taskRouter);

// Global Error Handler Middleware (MUST be registered AFTER routes)
app.use(errorHandler);

const PORT = process.env.PORT || 1230;

app.listen(PORT, async () => {
  await connectDb();
  console.log(`Server is running in ${process.env.NODE_ENV || "development"} mode on port ${PORT}`);
});
```

## Common Pitfalls & How to Avoid Them

| Pitfall | Cause | Solution |
| :--- | :--- | :--- |
| **`Cannot find module ... or its corresponding type declarations` on relative imports** | With `"moduleResolution": "NodeNext"`, Node requires explicit file extensions. | In TS files, import local modules using `.js` extensions (e.g. `import connectDb from "./config/db.js"`). TypeScript recognizes this maps to `./config/db.ts`. |
| **`Property 'user' does not exist on type 'Request'`** | Standard Express `Request` has no `user` property. | Add `src/types/express.d.ts` declaring global `Express.Request` extensions or define an `AuthRequest` interface. |
| **`Error handler not catching controller errors`** | Placing `app.use(errorHandler)` before routes. | Always place error handling middleware after all `app.use('/api/...', ...)` routes. |
| **`Mongoose enum validation error`** | Mismatch in case sensitivity between Schema enum and Controller strings. | Use a shared TypeScript union type (e.g. `export type TaskStatus = 'Pending' \| 'In Progress' \| 'Completed'`). |
